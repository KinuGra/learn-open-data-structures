# DLList: 重要ポイントまとめ（特徴・計算量）

## 🔑 特徴（3つだけ覚える）

1. **双方向ポインタ**: 各ノードが `next` と `prev` を持つ → 前後どちらにも辿れる
2. **ダミーノード（番兵）**: データを持たない空ノードで、先頭の前 = 末尾の後ろ = ダミー、として **循環構造** にする
3. **特殊ケース不要**: ダミーのおかげで「先頭/末尾の追加・削除」を場合分けせずに書ける

## ⏱ 計算量

| 操作                                     | 計算量                 | 理由                         |
| ---------------------------------------- | ---------------------- | ---------------------------- |
| `get(i)` / `set(i, x)`                   | **O(1 + min{i, n−i})** | i番目のノードを辿る時間      |
| `add(i, x)`                              | **O(1 + min{i, n−i})** | 探索が支配的、挿入自体はO(1) |
| `remove(i)`                              | **O(1 + min{i, n−i})** | 同上                         |
| ノード参照がわかっている場合の挿入・削除 | **O(1)**               | ポインタの繋ぎ替えだけ       |

> **本質:** DLListで時間がかかるのは「ノードを探す処理」だけ。**参照さえあれば全操作O(1)**。

## 🆚 配列ベースListとの違い

|                      | 配列List           | DLList               |
| -------------------- | ------------------ | -------------------- |
| i番目アクセス        | O(1)               | O(1 + min{i, n−i})   |
| 任意位置の挿入・削除 | O(n)（シフト必要） | O(1)（参照があれば） |

## 💡 応用ポイント

ノード参照を **USet（ハッシュ集合）** に保存しておけば、値→ノードの検索もO(1)になり、削除もO(1)で行える。
